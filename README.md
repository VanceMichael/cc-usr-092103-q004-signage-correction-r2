# 公共外语标识纠错闭环

保存公共外语标识问题、译写规范和整改过程的数据约定，并提供纠错闭环服务。

## 领域资料

仓库中的 `contracts/` 描述基础资料格式，`fixtures/` 给出可公开使用的示例：

- `context` —— 领域上下文（标识与版本约定）
- `standards` —— 公共场所外语标识英文译写规范，按版本只增不改
- `venues` —— 场所目录，含权属单位、责任单位与专业领域
- `personnel` —— 专家与志愿者的专业领域、语种与容量
- `sla` —— 派单、术语核对、单位确认、更换各环节的处理时限

所有示例均为虚构数据，不含真实个人信息、账号或访问凭据。

## 闭环服务（src/service.py）

`CorrectionService` 把市民上报到整改完成的全过程组织为**只追加**的事件流：

1. **上报**：照片先脱敏（人脸/车牌/二维码打码、设备信息抹除、坐标降精度），
   原片与真实上报人只入内部保险库；再按“场所 + 牌面文字”归并指纹并入既有案件，
   同一标识实体永远只有一个案件。
2. **派单**：按场所权属与专业领域自动派给容量内的专家，无人可派时进入待认领池，
   由匹配领域的专家或志愿者认领。
3. **办理**：术语核对（记录采用的规范版本）→ 责任单位确认（校验权属）→
   登记更换；任何环节可驳回，驳回或更换后可重开进入新办理周期。
4. **规范换版**：新版本只追加，已办结案件保留当时采用的版本，新案件用现行版。

一致性约束：

- 每个办理周期最多一条整改结论（更换或驳回），结论之后的异议须先重开；
- 同一 `report_id` 重复提交幂等，不产生重复事件；
- 离线补报（业务时间早于入库时间）归并为证据，结论之后拍摄的材料只标记复核，
  不另立新案、不生成第二条结论；
- 同一线索只保留一条办理线，重复认领被拒绝，材料改为归并；
- 事件带哈希链，`log.verify()` 可校验证据未被篡改。

## 两种视图

- `public_view(case_id)`：市民扫码可见——线索是否已归并、采用哪版译写规范、
  由哪个责任单位确认、何时完成更换；不含任何个人标识与内部材料。
- `internal_dossier(case_id)`：外事部门内部——从当前状态回到最初照片
  （保险库引用）、每次审校意见、现场回访与完整事件链。
