# 公共外语标识纠错闭环

保存公共外语标识问题、译写规范和整改过程的数据约定，并提供纠错闭环服务：
市民上传的线索照片经隐私处理与实体归并后，按权属与专业领域派给专家或
志愿者，术语核对、责任单位确认、更换、驳回、重开与规范换版全程只追加
记录；公众扫码可见整改结论，外事部门内部可回溯完整证据链。

## 领域资料

仓库中的 `contracts/context.schema.json` 描述基础资料格式，`fixtures/`
给出可公开使用的示例，均沿用 `domain` / `kind` / `version` 约定：

- `fixtures/context.json` — 领域上下文
- `fixtures/standards.json` — 译写规范（多版本，换版只追加新版本）
- `fixtures/venues.json` — 场所目录（含权属责任单位）
- `fixtures/personnel.json` — 人员能力（协调员 / 专家 / 志愿者，含领域与在办上限）
- `fixtures/slas.json` — 各环节处理时限

当前资料反映的事实包括：

- 市民可上传外语标识纠错线索
- 高校与翻译组织参与
- 线上平台提供规范查询和意见征集

## 服务设计（src/）

- `events.py` — 只追加事件存储：全局有序、按流版本化，追加时可声明期望
  版本做乐观并发控制，可选 JSONL 落盘、重启后折叠重建。
- `privacy.py` — 照片隐私处理：原件入受限证据库，脱敏副本剥离全部拍摄
  元数据并模糊敏感区域；公众视图只引用脱敏副本。
- `merging.py` — 实体归并：同一场所下文字一致或高度近似的线索归入同一
  案件，避免同一标识被拆成两个案件。
- `dispatch.py` — 派单规则：责任单位取自场所权属，承办人按专业领域优先
  专家、其次志愿者，受个人在办上限约束；处理时限随派单写入案件。
- `service.py` — 闭环服务：线索提交（离线补报按 clue_id 幂等）、认领
  （单承办人，冲突即拒）、术语核对（记录所用规范版本）、责任单位确认、
  更换、回访、办结、驳回、重开、规范换版，全部只追加事件。
- `views.py` — 两个投影：`public_case_view` 只含白名单字段（是否已归并、
  采用的规范版本、确认单位、完成更换时间）；`internal_evidence_chain`
  保留完整事件流，能从新牌面回到最初照片、每次审校意见与现场回访。

一致性约定：已有结论（已办结 / 已驳回）的案件必须先重开才能继续推进，
配合事件流的版本检查，离线补报或多人认领同一线索都不会产生两条互相
矛盾的整改结论；结论后到达的补报线索只作为证据附着，不推翻已有结论。

## 本地校验

```bash
pip install -r requirements.txt
python -m pytest
```

运行项目自带测试即可确认样例资料可读取、领域标识与版本字段完整，且
闭环流程、隐私边界与一致性约定均符合预期。所有示例均为虚构数据，不含
真实个人信息、账号或访问凭据。
